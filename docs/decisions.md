## 2. Standing rules

- The owner's standing delegation ("best choice") lets the facilitator decide; the decision is recorded here as Accepted and the mentor confirms it at the next gate.
- ~~Planning, documentation and direction work runs on Fable; code tasks run on Opus 5.5 at medium effort.~~ Superseded by DEC-022 (8): all delegated work, code and docs, runs on Opus 5.5 medium-effort subagents, in parallel with disjoint files; the main session coordinates.
- The facilitator drafts and never approves; every approval row stays `[Pending]` until the mentor signs.
- IDs are never renumbered or reused; a changed item is revised ("rev. 1"), withdrawn or superseded, with the successor named.
- Code may not differ from an accepted ADR, `docs/04-design/api/openapi.yaml` or `docs/04-design/data/schema.sql` without updating the contract in the same change.
- Facts, coordinates, hours, prices, distances and durations never come from a model; unknown IDs or fields in model output are validation failures. A model never publishes; publishing is the deterministic automated gate in code. A model-extracted fact is accepted only when it cites a supplied evidence id, passes code parsing (hours, price shapes) and contains no contact data; it is stored with `origin = AI_EXTRACTED`, a `STRONG`/`WEAK` grounding flag and its source link, and labelled "Summarised from sources" (DEC-028, relaxing the DEC-022 verbatim-quote rule). Distances and durations never come from a model.
- No copy, label or document may claim that content was reviewed by a human (DEC-022).
- Nothing is reported as verified on real providers, devices or bilingual content when only mocks or static checks ran.
- Dates are written `YYYY-MM-DD`; this log is the only place where decisions and open questions are maintained.
- Documents keep their names and locations (DEC-029); a change to scope, rules or design updates the kept document in the same change.
